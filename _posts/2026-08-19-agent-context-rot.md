有个现象很烦：

刚开始 Agent 挺靠谱。  
聊到第 N 轮，开始：

- 改已经改过的文件
- 忘记你说过的约束
- 自信满满地引用不存在的函数

我以前以为是「模型今天状态不好」。  
后来对照几次日志，更像是：**上下文窗口被垃圾信息占满了。**

## 典型垃圾从哪来

1. 大段终端输出反复贴回去
2. 全仓库搜索结果
3. 试错失败的中间文件内容
4. 你自己前后矛盾的补充指令

Agent 不是无限记忆。  
窗口有上限，旧的重要约束会被挤掉，或者淹没在噪音里。

## 我现在的应对

没什么高级技巧，就三条：

### 1. 任务拆开，宁可新开对话

「配后台 + 写三篇文章 + 修主题切换」这种大包，很容易把一轮对话搞成垃圾场。

拆成：

- 对话 A：只改配置
- 对话 B：只写文章
- 对话 C：只查 bug

贵一点就贵一点，总比改乱仓库便宜。

### 2. 关键约束写进 Rules / 文件，别只靠聊天记录

「别提交 .env」「只动 admin」这种，说一次不够。  
放进项目规则或点名文件路径，比埋在第 17 条消息靠谱。

### 3. 感觉它开始飘，就停

信号包括：

- 开始解释它没读过的文件
- 重复你已经否决的方案
- 问你已经回答过的问题

这时候继续聊通常是加刑。  
`/clear` 或新开一轮，把当前目标重说一遍，附上关键文件路径。

## 「记忆」产品别神话

现在很多工具宣传长期记忆。  
我对个人项目的态度还是：

> 能用，但不信任它替代清晰的任务描述。

真重要的约束，写进仓库里的规则文件。  
仓库是版本化的，聊天记录不是。

## 题外话

有时候不是上下文问题，是你自己需求变了，却没明确说「前面那套作废」。

模型很擅长同时服务两个互相打架的目标——然后产出一坨谁都不满意的折中。

所以飘的时候，先检查两件事：

1. 窗口是不是脏了
2. 指令是不是互相打架

多数情况，答案在这两项里。
